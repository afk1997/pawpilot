# Arham Always Care — WhatsApp Helpline Bot (V2)

Question-and-answer WhatsApp helpline for Arham Always Care, the animal-rescue project of Arham Yuva Seva Group. People ask for the animal-ambulance number for their area, hospital and clinic details, or how to donate or volunteer. The bot answers in English, Hindi, Marathi or Gujarati from the directory. It is not a dispatcher: there is no escalation queue, no follow-ups, no cron jobs. Arham runs most ambulances and partner NGOs run the rest; code labels a partner unit's number with its operator ("(operated by <partner>)", in the reply's language). **Life-and-death software: be conservative.**

Design spec: `docs/superpowers/specs/2026-09-25-v2-qa-helpline-design.md`. Implementation plan: `docs/superpowers/plans/2026-09-25-v2-core-bot.md`. Where the spec and the code differ, the code is right (see "Spec drift"). Setup and operations: `README.md`; the Azure VM: `docs/runbooks/deploy.md` and `docs/runbooks/restore.md`.

## Hard rules

1. **The model never types phone digits.** Tools return opaque handles; the reply carries `{{AMB:handle}}`, `{{CLINIC:handle}}` or `{{PHONE:helpline}}` tokens (or a `{{PHONE:<key>}}` that `get_info` returned for a number in `src/content/static.json`), and a hospital's or clinic's Google Maps link as `{{MAPS:handle}}` (the clinic handle its `{{CLINIC:…}}` token uses; `find_clinics` returns the token, never the link); `src/server/agent/render.ts` substitutes real numbers and links; `src/server/agent/scrub.ts` strips any other 7+ digit run after one corrective retry, and `src/server/agent/guards.ts` does the same with a link the model types to anywhere but the website (`WEBSITE_URL`'s host): a map link reaches a reporter only through the token. The stored template (what the next transcript shows) holds tokens, never digits or inserted map links: a number the model retyped goes in as its token. The public 102/108/112 emergency numbers are the only ones the prompt lets the model write.
2. **No dispatching language.** We hand over a number; the reporter calls. The dispatch guard asks for one corrected draft, then replaces offending sentences with the localized "Please call them directly and they will guide you.", keeping any number they held.
3. **Time to number is the metric.** When Claude is paused or fails, `src/server/worker/fallback.ts` still sends a directory card or the helpline number.
4. **Multilingual.** en / hi / mr / gu everywhere: cards, welcome and menu, fallback and system lines. Claude replies in the reporter's language and script; Latin-script Hinglish counts as `en` for the system's own lines, both in `detectLanguage` (`src/server/lang.ts`) and in the language Claude reports.
5. **Idempotent ingress.** Dedup by Interakt message id; one turn per conversation at a time (pg-boss singleton + advisory lock).
6. **Visible degradation.** Every failure is a `turns` row, an `events` row, a conversation flag or a health-endpoint signal. Nothing fails silently. A failed send is resent from its stored text by the worker's minute sweep (at most three attempts, never a new model call), and `/api/health` answers 503 when replies stop getting out (`checks.delivery`).
7. **Test conversations never reach Interakt** (`is_test`, phones `+91TEST_…`).

## Architecture

Interakt → `POST /api/webhook` (verify, dedup, store, enqueue) → Postgres + pg-boss `turn` queue → worker (`src/server/worker`) → Claude Sonnet 5 via `@anthropic-ai/claude-agent-sdk` (pinned 0.3.282, which bundles Claude Code CLI 2.1.282) under the owner's Max plan (`CLAUDE_CODE_OAUTH_TOKEN`) with three in-process tools → render + scrub → Interakt send. Every reply is written ahead (`src/server/worker/deliver.ts`): stored as `sending`, with the messages it answers marked, in one transaction before the send, so a retried job never answers a burst twice. Admin at `/admin` (password cookie) with transcripts and turn details; test harness at `/test-chat`; health at `/api/health`. The bot runs at helpline.arhamalwayscare.org; `WEBSITE_URL` (default https://alwayscare.org) is the public website the welcome, the menu and the prompt link to.

**Fast path** (`src/server/worker/fast-path.ts`, before any Claude turn): the conversation's first message with content (the welcome, menu and voice-note lines do not count), only text or labelled pins, at most 300 characters, with no entry of `OTHER_INTENT_WORDS` (words and short phrases for a clinic, doctor or hospital, donating, volunteering, a suggestion, a person, a complaint, a wrong number, a driver who does not answer and a hurt person, in en/Hinglish/hi/mr/gu: the common phrasings, not every one) and matching exactly one unit by area or city gets that unit's card (with its hours line when the unit publishes hours) without the model, even while Claude is paused. It stays with the model when the words also name another directory city (`other_city`), or when an area match goes only through area names holding a common locality word (`GENERIC_AREA_WORDS`: nagar, town, road, west, …) or doubling as an everyday word or surname (`EVERYDAY_AREA_NAMES`: satellite, ghuma, ambli, hazra, ghorpadi, …) and the unit's city is not named (`generic_area`), or when the match goes only through a city name that is also an everyday word (`EVERYDAY_CITY_NAMES`: surat, a face in Hindi/Urdu) that does not read as a place ("surat me", "in surat", "સુરતમાં", "Adajan, Surat" and "Surat" alone do; "kisi bhi surat mein", in any case, and "kutte ki surat se khoon", the dog's face, do not; `everyday_city`) and the conversation does not know that city; the runner logs why it did not fire at debug level. It writes a `turns` row with model `fast_path` (status ok, the handle and structured output written before the send; the location is the unit's city, and its area only when the reporter named it), a system reply whose template holds `{{AMB:<handle>}}` instead of the digits (any other phone-shaped run in the unit's cells masked), and a `fast_path` event; no flag. Every later message goes to Claude. A failed check records `fast_path_error` and Claude answers. `FAST_PATH_ENABLED=false` turns it off once the worker starts with it, no deploy: on the VM `arham up -d`, which re-creates the worker (`arham restart` keeps the environment a container was created with).

**First contact** (`src/server/worker/first-contact.ts`, `turn-runner.ts`): only a burst of nothing but greetings, or the menu word, gets the welcome list. A first message with content is answered directly, never the list first: the voice-note line, the fast path's card or Claude's reply, the last two opening with a one-line greeting (Claude's turn prompt carries `FIRST CONTACT`). First contact means no reply has been written yet, sent or not (`isFirstContact`: no assistant message, whatever its delivery status, read from the messages rather than the welcome claim), so a turn retried after a failure still greets. Replies are short by rule: the system prompt asks the model to match the reporter's length, to ask for the place in one line, never to describe the helpline unless the reporter asks about us (then from `get_info`) or repeat the menu, and to give `{{PHONE:helpline}}` only when it cannot help.

**Pre-matched units** (`prematchAmbulances` in `src/server/agent/tools.ts`): before a Claude turn's first call, the matcher runs on the reporter's words, and, when they match no place, on the location known so far. An exact area or city match of one to three units issues their handles, and the turn prompt lists them under `PRE-MATCHED UNITS` (an area match names the covered area it went through: "covers Vikhroli"; a unit's published hours follow: "hours 10am-7pm IST"): Claude can give the number in one call instead of looking it up first. Only a match on the reporter's words sets the tool's state (so the card fallback works); units for the known location come under their own header (reuse only if the reporter still needs that place) and never arm the card, so a reply about another place never carries the earlier place's card. A match on the words that the fast path's precision rules reject (another covered city named, only generic area names without the unit's city, or an everyday city name with no locative cue) is not pre-matched at all: no block, no handles, no card; Claude looks the place up itself, and the `prematch` record says why (`skipped`). Nor is a burst holding a clinic, hospital or doctor word (`FACILITY_WORDS` in `src/server/directory/matcher.ts`, which also open the fast path's `OTHER_INTENT_WORDS`): the reporter wants the facility (`find_clinics`), so neither the words' units nor the known location's are offered (`skipped: other_intent`). The city the conversation already knows counts: a unit in another city is pre-matched only when the words name that city, and a generic area name in the known city is precise. Looser matches or more units add nothing. The turn's `toolCalls` audit lists the attempt first as a synthetic `prematch` record.

**Hours, hospitals and clinics.** The directory CSV has optional `Hours` and `Address` columns (after `Operated By`): `ambulances.hours` (migration 0004), and the `clinics` table's `hours` and `address`, are written as the file has them, and the ingest warns about a phone-shaped run in either like any text cell. The site publishes hours for the nine Mumbai units (10am–7pm IST), the Ghatkopar, Kandivali (Pawandham) and Junagadh hospitals and the Rajkot clinic (10am–11pm IST) and the Ludlow hospital (9am–6pm IST, with its address); Paramdham publishes none. Every card (`src/server/messages/cards.ts`: the fast path's, the fallback's, the one a tokenless reply gets) adds a localized line when a unit has hours ("Hours: 10am–7pm IST (call to confirm)", hi समय, mr वेळ, gu સમય), the hours as the directory holds them; `renderNumberForToken` stays the number, since inside its own sentence the model says the hours. `find_ambulances` and `find_clinics` return hours (and a clinic's address) after the tool-boundary scrub, which writes the en dash as a hyphen. The prompt's rule 10 says them in one clause and still gives the number outside them. The hospitals and the clinic share the `clinics` table, the `clinic` intent, `find_clinics` and `menu:clinic`; only the words say "Hospitals & clinics" (welcome, menu, prompt, coverage list), and a facility's label says which it is.

**Hospital and clinic locations.** After `Address` the CSV has optional `Maps`, `Page`, `Services` and `Notes` columns, read on clinic rows only: `clinics.maps_url`, `page_url`, `services` and `notes` (migration 0005), written as the file has them. `Maps` is the facility's Google Maps location and nothing else: `MAPS_URL_RE` in `src/server/links.ts`, `https://maps.google.com/?q=<lat>,<lng>` with at most six decimals (so no 7-digit run, no other host, path, query or text). `Page` is its page on the website (`websitePageRe`: the host of `WEBSITE_URL`, with or without www, and a path of letters, digits, "/", "_" and "-"). The ingest refuses a clinic row whose `Maps` or `Page` is anything else (the script passes `WEBSITE_URL`, or its default), warns about a phone-shaped run in any of the four like any text cell, and its parse line counts the clinics with a map link. `find_clinics` returns per facility its handle, `phone` (the `{{CLINIC:<handle>}}` token), `maps` (the `{{MAPS:<handle>}}` token, null unless the stored value is a `MAPS_URL_RE` link: `mapsLink` in `src/server/links.ts`, which the renderer and the clinic card apply too, so a hand-edited row cannot bypass the ingest), `address`, `hours`, `services`, `notes` and `page` (null unless a page on the website), all through the tool-boundary scrub. The renderer resolves `{{MAPS:<cli_handle>}}` to the active facility's link through the same slots as numbers (never cleaned, never cut: whole or not at all), lists it in `RenderResult.links`, and drops the token like an unknown handle when the facility has no link; the sent template keeps the token. The digit guard masks inserted links before its scan (`splitAllowed` in `src/server/agent/scrub.ts`: an allow-list entry starting with http(s):// is matched as written), the dispatch guard skips links (`withoutLinks`) and never reads sending a location, address, map, link, number or details as dispatching (see Guard residuals), and a replaced dispatch sentence's link goes back after the call-directly line, as its numbers do. A dropped MAPS token counts like a dropped AMB or CLINIC one (the helpline card when no number is left; the stale-handle correction for a retired facility). A link the model types is treated like typed digits (`typedLinks` and `stripLinks` in `scrub.ts`, `LINK_CORRECTION_NOTE`): any http(s) link off the website's host, or a map host written without its scheme (maps.google…, goo.gl/maps, maps.app.goo.gl, google…/maps), gets one correction and is then stripped from the text and the template (with any brackets that held only it), with a `link_strip` event; a reply the strip leaves with no number and no inserted link gets the helpline card, as for a dropped token. Code-inserted links are kept apart, so they are never touched, and the renderer puts a space after an inserted link when text glued to it could continue a URL ("{{MAPS:x}}/extra"), in the text and the template alike. The prompt's hospitals rule: always the facility's number (`{{CLINIC:<handle>}}`), then what the reporter asked for, each from the result ("where is it", the address, the location, the map or directions get its `{{MAPS:<handle>}}` token after "Google Maps:" and the address; services or notes when asked), plus its hours, or a line to call before visiting when it publishes none, in about three short lines. `buildClinicCard` (no reply uses it yet) has a "Google Maps:" line under the address, and the FAQ's hospital entry says the bot shares addresses and map locations on request.

## Claude backend (`src/server/agent/claude-code-backend.ts`)

The CLI runs locked down. Do not loosen any of this without the owner:

- `tools: []`, with the built-in tool names and `mcp__claude_ai_*` also in `disallowedTools`: no shell, file or web tools. The model has only the three `mcp__arham__*` tools and the CLI's `StructuredOutput`, which carries the reply.
- `permissionMode: "dontAsk"`: a tool call `allowedTools` does not pre-approve is denied without a prompt. Not `bypassPermissions`, which the CLI refuses to run as root.
- `strictMcpConfig: true` (and `ENABLE_CLAUDEAI_MCP_SERVERS=false` in the child env): only the in-process `arham` server loads; no user, project or claude.ai connector servers.
- `verbatimPrompts: true`: reporter text is part of the prompt, so an `@path` mention in it must never be expanded into a file read (`/proc/<pid>/environ`, say) and a `/command` never run. `src/server/agent/transcript.ts` also rewrites an `@` before a path, as a second layer.
- An env allowlist (`buildChildEnv`; the SDK does not merge `env` with `process.env`): PATH, locale, TZ, TMPDIR, CA and proxy variables, HOME set to `LLM_HOME_DIR` with the config dir inside it, and the OAuth token. The database URL, Interakt key, admin secrets and a parent Claude Code session's variables never reach the child. Because HOME and the config dir are its own, a `claude login` made on the machine is not seen either: the worker needs `CLAUDE_CODE_OAUTH_TOKEN`.
- `settingSources: []`, `persistSession: false`, `cwd` = `LLM_HOME_DIR`: no user or project settings or CLAUDE.md are loaded, and no session transcript is saved.
- The init check is strict: the init message must list the three arham tools and nothing else but `StructuredOutput`, with `arham` connected, or the turn aborts as TRANSIENT (`mcp_not_connected: …` in the turn's error) and falls back. A CLI that changes that list sends every turn to the fallback.

The owner's smoke run is the go-live gate, and must be re-run after any `@anthropic-ai/claude-agent-sdk` upgrade: `RUN_CLAUDE_SMOKE=1 npx vitest run tests/smoke`, from a terminal outside Claude Code, with `CLAUDE_CODE_OAUTH_TOKEN` exported in that shell (README, "Go-live gate"). It is also the only check that `StructuredOutput` returns the reply under `dontAsk` against the real API.

Failure classes: LIMITED and AUTH pause Claude for every conversation (`worker_state`); INVALID_OUTPUT, and a TRANSIENT failure that was not a timeout (the backend's `timedOut` flag), get one retry inside the turn's 100 s budget; whatever still fails goes to the fallback.

Extra usage is off: `LLM_ALLOW_EXTRA_USAGE` defaults to `false` (the owner's decision; the owner also keeps it off in the account). A rate-limit rejection that extra usage paid for anyway still counts as the limit: the reply that came back is delivered (a rejected limit never pre-empts a valid result in `classify`), the turn makes no further call, then Claude pauses until the reset and a `claude_limited` event with `extraUsage: true` is recorded. Every turn extra usage paid for records a `claude_extra_usage` event. With the flag on, such turns run without the pause.

## Guard residuals (known gaps, not bugs to rediscover)

- The reply scrubber reads a run as digits joined by at most one space, line break or hyphen. It misses dotted or spaced-dash groups ("98765.43210", "98765 - 43210"), runs of several dash characters ("98765--43210"), slashes, commas, brackets, and a number split across sentences or lines. The other way round, a run can also form across a line break between two numbers: an address line ending in a PIN code ("…, Mumbai 400077") right above a line starting with a digit ("10am–11pm IST") reads as one 8-digit run, which gets a corrective call and is then stripped from both lines (the stored addresses end in ")", so it is unlikely). The tool-output scrub has the same separator gaps. Full list: the `DIGIT_RUN_RE` comment in `src/server/digits.ts`, the one module both patterns live in.
- The dispatch guard has no Latin-script Hinglish vocabulary yet ("ambulance bhej rahe hain" and "gaadi aa rahi hai" pass); adding it waits for an eval pass on the real model. Its Indic "is coming" and "on the way" rules fire only with an ambulance or team word right before the phrase (precision first).
- The tool-boundary scrub (`scrubToolText` in `src/server/agent/tools.ts`) removes every phone-shaped run from what a tool returns before the model sees it, so the model cannot relay a non-phone number from the directory. The coverage summary in the system prompt (`src/server/directory/coverage.ts`) is scrubbed the same way. The no-LLM fallback card, though, shows a unit's area, city, operator and hours as the directory holds them: `npm run ingest:ambulances` warns about a phone-shaped number in any text cell, Hours, Address, Maps, Page, Services and Notes included (it does not refuse the file).
- A map link goes into a reply as the directory holds it, and the digit guard masks it as code's. Only a `MAPS_URL_RE` link is ever inserted (at most six decimals per coordinate, so no 7-digit run, and no other host, path or text), checked at the ingest and again by the renderer and `find_clinics`; a wrong pin within that shape still goes out as written. The dispatch guard skips every http(s) link in a reply, so dispatch wording inside a link is never caught (no directory link holds any).
- A link the model types to the website passes as typed (an invented page path would reach the reporter), and a link to another host written without "http(s)://", other than the map hosts, is not read as a link (its digits still meet the digit guard).
- Sending information is not dispatching, narrowly: when in doubt the guard fires (`NOT_SENDING_INFO_EN` and `NOT_SENDING_INFO` in `src/server/agent/scrub.ts`). In every language the sentence must name nothing else sent (`AGENT_MENTION`: help, an ambulance, vehicle, van, rickshaw, auto, car or bike, a team, unit, crew or NGO, a driver, doctor, vet, rescuer, volunteer, worker, member, responder, person, man, staff, people or someone, and आदमी, व्यक्ति, लड़का, माणूस, માણસ and the like; a word that only says whose information it is, "the ambulance's number", "एम्बुलेंस का नंबर", "the ambulance number", does not count, but "with", "for" or "to" it does, "एम्बुलेंस के साथ"), and information words are matched whole, so "अस्पताल" never holds "पता". What still fires costs one corrective draft, then the call-directly line with the sentence's numbers and map link kept but an address in it lost; Latin-script Hinglish is read neither way (above). Around a place word the exemption is an allow-list, and a number keeps main's reading:
  - English place nouns (location, address, map, link, pin, photo, directions; "location pin" and "Google Maps link" count as one; `PLACE_OBJECT`): before the noun only "you", "the", "a", "an" or "this", a facility owner ("the hospital's", "the Ghatkopar hospital's", "the hospital location") and "Google"; after it only the sentence's end, a colon, a link or token, "and" another information noun, "of" a facility, or "for you"/"to you". "Your location", "the dog's location", "them the location", "the location of the dog", "the location for pickup", "the location you shared" and "the location pin now" fire.
  - English numbers (number, contact, details; `NUMBER_OBJECT`), as main reads them: after an optional "you" and a determiner (never "your") and the owners main allowed ("the driver's", "the ambulance driver's phone", "the helpline"), with no "to" after them in the sentence ("the number to call" fires) but "to you". A place noun later in the sentence must be joined to the number by "and" and pass the place rules: "the number and the dog's location" and "the number with the location of the dog" fire.
  - Hindi, Marathi and Gujarati place words (लोकेशन, पता, पत्ता, नक्शा, लिंक, લોકેશન, સરનામું, …; never a glued locative such as पत्त्यावर or સરનામે, and पता before है or नहीं is "know"): right before the verb (one adverb such as अभी may stand between), with only `PLACE_PREFIX_WORD`s before them in their sentence. Those are the subject (हम, मैं, आम्ही, मी, અમે, હું), the reporter as recipient (आपको, आप को, तुम्हाला, તમને, आपके लिए, तुमच्यासाठी, તમારા માટે), a facility owner (अस्पताल की, हॉस्पिटलचा, હોસ્પિટલનું, एम्बुलेंस का), an adverb (अभी, आता, तुरंत, लगेच, હમણાં), another information word and "and" (नंबर और), and यह, ये, वह, ही, हे, तो, આ, એ, તો. Anything else fires: a recipient other than the reporter (उन्हें, त्यांना, તેમને), वाला or વાળું, इथला or तिथली, any other noun, pronoun or possessive ("कुत्ते की", "हमारे अस्पताल की", a facility's name before the facility word, "घाटकोपर अस्पताल का पता"), a comma or an interjection before them ("जी, हम लोकेशन…"). A place word off the list within four words before the verb fires even when a number word stands nearer the verb (`PLACE_OFF_LIST_BEFORE_VERB`: "हम उन्हें लोकेशन और नंबर भेज रहे हैं").
  - Hindi, Marathi and Gujarati number words (नंबर, संपर्क, जानकारी, माहिती, तपशील, નંબર, …): within two words before the verb with no destination or recipient marker (`MARKER`: पर, को, तक, ला, ने, में, से, પર, ને, …) between, and never the reporter's (`REPORTERS`: "आपका नंबर", "आप का नंबर").
- `src/content/static.json` is tokenized at load: in `donate` and `volunteer`, only a field whose name says it holds a phone (`phone`, `contact`, `mobile`, `helpline`, `whatsapp` or `number` in the name, and none of `account`, `ifsc`, `upi` or `bank`) turns its number into a `{{PHONE:<key>}}` token, which goes out formatted as a phone number. Any other field passes through and the tool-boundary scrub removes its runs, so a bank account, IFSC or digit UPI id can never be relayed: keep them on the website (the bot gives the donate URL), or add a non-phone `{{ACCOUNT:<key>}}` token first. The free text of `about`, `human_emergency` and the FAQ still reads every 7+ digit run as a phone number (the FAQ's Animal Helpline India number relies on it): only phone numbers belong there.
- Handles resolve from the handle maps of a conversation's last 20 turns (`loadConversationHandles` in `src/server/worker/persist.ts`): a handle from an older turn gets the unknown-handle correction.
- The fast path reads the reporter's words alone. It leaves a burst to the model when the words name a directory city other than the matched unit's (`other_city`: "Ghatkopar, Pune"), or when an area match goes only through area names holding a common locality word (`GENERIC_AREA_WORDS` in `src/server/directory/matcher.ts`: Model Town, Vijay Nagar, Mira Road) or that are also everyday words, verb forms or surnames (`EVERYDAY_AREA_NAMES`, curated from the directory: Satellite, Ghuma, Ambli, Khadki, Lokhandwala, Hazra, Andheri, Khar, Sela, Ghorpadi), and the words do not name the unit's city (`generic_area`: "ambli na jhad pase kutru ghayal che", "ghorpadi disli" (monitor lizards) and "Hazra ji ka kutta ghayal hai, Lucknow" go to the model), or when the match goes only through a city name that is also an everyday word (`EVERYDAY_CITY_NAMES`: surat, सूरत a face, and a case in idioms) that does not read as a place (`everyday_city`: "kutte ki surat pe chot hai"); the Claude turn's pre-match on the words follows the same rules (`precisionIssue`). The rule is as ruled (`cityCueNear`): in/at/near right before the name make it a place whatever comes earlier ("the dog is in Surat"); otherwise a word of `FACE_WORDS` within the two words before it makes it a face or an idiom whatever follows (possessives ki, ka, ke, uski, iski, की, का, के, उसकी, ની, નો, ના, ची, चा, चे; this, that, any, every, also, such, whole: is, us, kisi, har, bhi, aisi, aise, puri, poori, इस, उस, किसी, हर, भी, ऐसी, ऐसे, पूरी, આ, એ, કોઈ, દરેક, આખી, ही, त्या, कोणत्याही, प्रत्येक, पूर्ण), so "kutte ki surat se khoon aa raha hai", "kisi bhi surat mein" and "kutte ki puri surat me khoon hai" go to the model; and otherwise the name alone, a glued locative case suffix, the bare name as the last word ("Adajan, Surat") or me/mein/mai/main/madhe/madhye/ma/maa/se/mathi/city/shehar/में/मे/मध्ये/માં/થી/શહેર right after it make it a place ("surat se hun"). "to" is no cue: it is also the Hinglish particle तो. A face word three or more words back ("kutte ki naak aur surat se khoon aa raha hai"), an unlisted possessive (meri, unki) or one glued to the noun ("કૂતરાની સૂરતમાં", "कुत्र्याची सूरत मध्ये"), with a cue after the name, or a face-sense "surat" ending the message with no face word before it, still reads as the city: then the pre-match offers the Surat units and arms their card, so a tokenless ambulance reply asking for the place would carry it. On the safe side (only slower): "surat, injured dog", "going to surat with the dog", a city-level pin "Surat, Gujarat", English "is" or "us" right before the name ("help us, surat me kutta ghayal hai"), and "ના, સુરતમાં" (Gujarati ના is also "no") wait for the model. The everyday list is curated, so an everyday-word area name missing from it still fires the fast path when no covered city is named, and so does a distinctive area name that an uncovered city also has ("Shalimar Bagh, Srinagar" gets the Delhi unit); a new directory area name that is an everyday word belongs in `EVERYDAY_AREA_NAMES`, a new city name that is one in `EVERYDAY_CITY_NAMES`. "andheri" is the one deliberate latency trade-off there: it is also Hindi for "dark" ("andheri raat", "andheri gali"), so a first message naming Andheri without Mumbai waits for the model (it still gets the number) rather than risk the Andheri card reaching a dark lane in another city; dropping it from the list trades that back. The card names the unit's area or city, so the reporter can see it. `OTHER_INTENT_WORDS` matches at the start of any word, so a few rescue reports go to the model (the safe side, only slower): "बंद" (switched off) also matches "बंदर" (monkey), "admi" matches "admit", "utha" matches "utha lo" (pick it up), "not responding" matches "the dog is not responding", and "bachche ko gaadi" matches a puppy hit by a car ("kutte ke bachche ko gaadi ne maara"). It holds the common phrasings only: an unlisted way of saying the driver does not answer, or that a person is hurt, still gets the unit's card. `FAST_PATH_ENABLED=false` turns the fast path off.
- A worker that dies between an Interakt send and recording its outcome leaves the reply `sending`; the resend sweep sends that stored text again after 2 minutes, so the reporter may get the same reply twice (never a different one).

## Spec drift (the code is right)

- Env names: `LLM_BACKEND`, `LLM_MODEL`, `LLM_EFFORT`, `LLM_MAX_TURNS`, `LLM_TURN_TIMEOUT_MS`, `LLM_HOME_DIR`, `LLM_TOKEN_ISSUED_AT`, `LLM_ALLOW_EXTRA_USAGE`, plus `CLAUDE_CODE_OAUTH_TOKEN` (`src/server/config.ts`). The spec's other `CLAUDE_*` names do not exist. Its deployment variables (`POSTGRES_PASSWORD`, `PUBLIC_HOSTNAME`, `ACME_EMAIL`, `AZURE_BACKUP_SAS_URL`) are read by `docker/docker-compose.yml`, Caddy and the backup service, never by `src/server/config.ts`; its geocoding variables (`NOMINATIM_*`, `GOOGLE_GEOCODING_API_KEY`) are not read yet.
- §5.4: `permissionMode` is `dontAsk`, not `bypassPermissions`; HOME, config dir and cwd all come from `LLM_HOME_DIR`.
- §5.12: `src/server/interakt/client.ts` sends two payloads only. Each is a `POST` to `INTERAKT_API_BASE` with `Authorization: Basic <INTERAKT_API_KEY>` and a 15 s timeout, carrying `{ countryCode, phoneNumber, callbackData: "agent" }` plus:
  - `Text`: `type: "Text", data: { message: <text> }`;
  - `InteractiveList`: `type: "InteractiveList", data: { message: { type: "list", body: { text }, action: { button, sections: [{ title, rows: [{ id, title, description? }] }] } } }`.

  There is no Template payload (none is kept for later) and no admin reply box. A number starting with "+" is split by the ITU country-code table; bare numbers follow the India rules in `splitPhone`. `+91TEST_` phones are refused.
- §5.7: handles are `amb_`/`cli_` plus eight letters a–p, so a handle never holds a digit.
- §5.2: turn jobs expire after 240 s, above the Claude turn's 100 s budget. A failed Interakt send is not retried through pg-boss (that would run the model again): the worker's minute sweep resends the stored reply when the send failed with no response, 429 or a 5xx, or was left `sending` for over 2 minutes, at most three attempts in all and only within 10 minutes; the last failure records `outbound_failed` and flags `send_failed`. On stop the worker takes no new turn at once, and a resend pass finishes only the send it had started.
- §5.14: Latin-script Hinglish is `en`, not `hi`, for the system's own lines.
- §5.10: the fallback gives a unit's number only for an exact area or city match with one to three units; anything looser gets the helpline card.
- §8 (`docs/runbooks/deploy.md`):
  - The worker runs `node --import tsx src/server/worker/index.ts`. Not `node dist/worker.js`, and not `npm run worker`, whose `sh -c` swallows the SIGTERM of a graceful stop.
  - Backups are `pg_dump -Fc | gzip` into `/opt/arham/backups` with 30 days kept on the VM, plus an optional curl PUT Blob through `AZURE_BACKUP_SAS_URL` (a Create-only SAS; a Blob lifecycle rule deletes old copies). Not supercronic and azcopy.
  - The images are built on an x86-64 VM, not arm64.
  - `scripts/deploy.sh` migrates with `docker compose run --rm app npm run migrate` before `up`, runs detached from the ssh session, and succeeds only once the new worker has started.
  - `/opt/arham/.env` is owned by the deploy user (`azureuser`), mode 600, since compose reads it as that user.
  - A changed setting applies with `arham up -d`; `arham restart` keeps a container's old environment.
- §5.15: there is no middleware; each admin and test-chat page and API route checks the cookie itself. Their JSON posts, the login's included, go through `readAdminJsonPost` (`src/server/admin/json-post.ts`: 403 cross-site, 415 not JSON, 413 oversized, all before anything else; the login reads an unusable body as a wrong password), and every such API route answers 503 with a data-free log line when the database fails. The admin page is read-only and polls.

## Working here

- Local: `docker compose -f docker/docker-compose.dev.yml up -d`, `npm run migrate`, `npm run ingest:ambulances`, `npm run dev` and `npm run worker:dev`. `LLM_BACKEND=fake` gives canned replies without Claude (refused when `NODE_ENV=production`).
- Tests: `npm run test:unit` (`tests/unit`) and `npm test` (everything) both need the dev Postgres, because the global setup migrates `arham_test` first; `resetDb` refuses any database whose name does not end in `_test`. The smoke test is skipped unless `RUN_CLAUDE_SMOKE=1`, and `tests/setup.ts` drops `CLAUDE_CODE_OAUTH_TOKEN` from every other run.
- Evals: `npm run eval` uses the scripted fake backend by default and skips the nine scenarios that need the real model (among them `28-human-hit-dog-claude`: that the word "human" alone does not flag a conversation is checked only there, since scenario 12's script decides it on the fake backend); `npm run eval -- --backend claude` spends Max usage. The runner turns the fast path on, regardless of `.env.local`, and judges a fast-path turn as code (like the fallback's), never as a model reply. The runner uses `TEST_DATABASE_URL` and, since it truncates every table, refuses (exit 2) unless the database it connects to, read with `current_database()`, is named `*_test` (`-- --allow-db` overrides).
- Anything that spends Max usage (the smoke test, `--backend claude` evals, a worker with `LLM_BACKEND=claude-code`) is started by the owner from a terminal outside Claude Code, never from an agent session.
- Change the prompt (`src/server/agent/prompt.ts`) only with the eval suite green on the real model (`-- --backend claude`); the fake backend never reads the prompt.
- Before committing: `npm run typecheck && npm run lint && npm test`. History is never squashed; PRs merge with a merge commit.
- `ambulances-clinics.csv` is gitignored (driver personal numbers). `.codex/`, `.mcp.json` and the `.env` files (all but `.env.example`) are gitignored.
